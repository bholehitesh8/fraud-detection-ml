🎓 Viva Voce Defense Questions & Answers

Essential academic defense questions covering Machine Learning principles, accounting constraints, and production design.

Q1: What is the main objective of this project?

Answer: To construct a real-time predictive surveillance system that identifies fraudulent online banking transactions using supervised Machine Learning. The system precalculates domain balance anomaly indicators, normalizes multi-currency transfers into USD, evaluates fraud probability in <100ms, and logs all outcomes in an auditable SQLite database.

Q2: Why is raw Accuracy an invalid evaluation metric for financial fraud?

Answer: Financial transaction datasets exhibit extreme class imbalance (96.5% legitimate vs 3.5% fraud in this benchmark). A naive model that classifies 100% of transactions as legitimate achieves an apparent 96.50% Accuracy while failing to intercept even a single fraud dollar (0% Recall, 0% F1). Thus, Fraud Class F1-Score (harmonic mean of Precision and Recall) and ROC-AUC are the mathematically valid criteria for model selection.

Q3: Which Machine Learning algorithm was selected and why?

Answer: ExtraTrees (Extremely Randomized Trees). On the 1,200 unseen test instances, it achieved a perfect 1.0000 Fraud F1-Score, 100% Recall (42/42 fraud caught), 1.0000 ROC-AUC, and 0 false positives. By randomly selecting split cut-points across 100 trees, ExtraTrees significantly reduces variance and prevents overfitting on skewed financial numbers.

Q4: How did you handle class imbalance without generating fake data via SMOTE?

Answer: Financial transactions are bound by strict mathematical accounting equations (e.g. $NewBalance = OldBalance \pm Amount$). Blind synthetic oversampling (SMOTE) generates synthetic interpolations that violate accounting conservation laws and distort real-world distribution boundaries. Instead, we use balanced class weights ($W_{fraud} = 14.2857$), inversely penalizing minority classification errors during optimization without feature corruption.

Q5: What is Data Leakage and how is it rigorously prevented?

Answer: Data leakage occurs when test set parameters (such as medians, IQR scaling boundaries, or one-hot categories) bleed into the training phase. In our pipeline, stratified train-test splitting (80/20) is executed before preprocessing. The ColumnTransformer pipeline is fitted strictly on X_train, and X_test is transformed solely using those learned parameters.

Q6: Why is RobustScaler preferred over StandardScaler for financial transactions?

Answer: Financial transaction amounts follow heavy-tailed power-law distributions with massive outliers (e.g. $10 micro-payments up to $500,000 corporate transfers). StandardScaler relies on sample mean and standard deviation, which are severely biased by extreme values. RobustScaler uses the median and Interquartile Range (IQR = $Q_3 - Q_1$), guaranteeing robust, outlier-immune scaling.

Q7: How does the system handle multi-currency transactions and account privacy?

Answer: The API validates standard ISO 4217 currency codes (USD, EUR, INR, GBP, etc.) and normalizes monetary values into baseline USD prior to ML inference using reference exchange rates. For privacy, customer account numbers are sanitized and masked (e.g. ******7890) before database persistence and server logging.
